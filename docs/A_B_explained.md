# Части A и B: что происходит и зачем

Разбор блокнотов [`A_setup.ipynb`](../notebooks/A_setup.ipynb) и [`B_environments.ipynb`](../notebooks/B_environments.ipynb) для тех, кто только начинает с Python. Сначала общая картина и основы, потом каждый шаг построчно, в конце — что делать при ошибках.

## 1. Зачем нужны части A и B

Дальше в дипломе модели будут «забывать» знания, а атаки — пытаться их вернуть. Всё это считается на GPU в Google Colab. Части A и B готовят для этого почву.

- **Часть A** — доступы и место: подключить Google Drive, создать папки, задать переменные окружения, подключить токен Hugging Face, проверить GPU и записать её характеристики в журнал.
- **Часть B** — два «окружения» Python со всеми нужными программами:
  - `unl` — для обучения и оценки моделей фреймворком OpenUnlearning;
  - `atk` — для атак и анализа: vLLM, spaCy, BERTScore и другие.

**Окружение** — отдельная папка со своим Python и своим набором пакетов (библиотек). Окружений два, потому что их пакетам нужны несовместимые версии одних и тех же библиотек. OpenUnlearning проверен с torch 2.4.1 и transformers 4.51.3, а vLLM требует torch 2.10. В одном окружении они бы конфликтовали.

**Lock-файл** — текстовый файл со списком всех пакетов окружения и их точных версий. По нему окружение можно собрать заново ровно таким же — через месяц, в новой сессии Colab или на другом компьютере. От этого зависит, воспроизведутся ли числа в дипломе.

## 2. Где что лежит

| Где | Что | Что с ним происходит |
|---|---|---|
| GitHub | блокноты и код | хранится всегда, с историей изменений |
| Google Drive, `MyDrive/unlearning_data/` | чекпоинты (`saves/`), результаты атак (`results_raw/`), lock-файлы (`envs/`), журнал `journal.md` | хранится всегда; на Windows эти файлы видны через Google Drive для компьютера |
| Диск машины Colab, `/content/` | окружения (`/content/envs/`), кэш и модели (`/content/fast/`), копия OpenUnlearning (`/content/sandbox/`) | **стирается**, когда сессия Colab заканчивается |

Правило простое: всё, что нельзя потерять, сразу пишется на Drive. Всё, что можно скачать или собрать заново, лежит на быстром диске машины.

## 3. Как устроен блокнот Colab

- Блокнот состоит из **ячеек**. Текстовые ячейки — пояснения, в ячейках кода — команды. Ячейка запускается кнопкой ▶ слева или сочетанием **Shift+Enter**.
- Ячейки выполняются **по порядку**, сверху вниз. Переменные, созданные в одной ячейке, видны в следующих, пока не закончится сессия.
- За ячейками стоит **машина Colab** — временный компьютер с GPU. После отключения (закрыли вкладку надолго, **Runtime → Disconnect and delete runtime**, закончилось время) она стирается. Поэтому ячейки со старта сессии выполняются каждый раз заново.
- **Runtime → Restart session** перезапускает только Python. Файлы на машине при этом остаются, а переменные Python и переменные окружения пропадают — после перезапуска снова выполните старт сессии.

### Три вида строк в ячейках кода

| Как выглядит | Что это |
|---|---|
| обычная строка, например `os.makedirs(...)` | код Python |
| строка с `!` в начале, например `!nvidia-smi` | команда терминала Linux, выполняется одна эта строка |
| первая строка ячейки `%%bash` | вся ячейка — скрипт терминала (bash), строки выполняются по очереди |
| первая строка ячейки `%%writefile путь` | Colab ничего не выполняет, а записывает текст ячейки в файл |
| `x = !команда` | выполнить команду терминала и сохранить её вывод в `x` — список строк |

В строках с `!` и в ячейках `%%bash` запись `$ИМЯ` подставляет **переменную окружения**, например `$BIG`. Всё после `#` — комментарий: пояснение для человека, компьютер его пропускает.

## 4. Мини-справочник Python — только то, что есть в блокнотах

| Запись | Что значит |
|---|---|
| `import os` | подключить модуль (набор готовых функций) `os` |
| `from google.colab import drive` | взять из модуля `google.colab` только часть `drive` |
| `DRIVE = "/content/..."` | создать переменную `DRIVE` и положить в неё строку (текст в кавычках) |
| `DRIVE + "/saves"` | склеить две строки: получится `"/content/.../saves"` |
| `print("Готово", x)` | напечатать текст и значение `x` через пробел |
| `f"Дата: {today}"` | f-строка: вместо `{today}` подставится значение переменной |
| `f"""..."""` | то же, но текст на несколько строк |
| `["PYTHONPATH", "MPLBACKEND"]` | список — несколько значений по порядку |
| `x[0]` | первый элемент списка `x` (счёт идёт с нуля) |
| `whoami()["name"]` | вызвать функцию `whoami`; она возвращает словарь (пары «ключ — значение»), а `["name"]` берёт значение по ключу `"name"` |
| `for name in список:` + отступ | цикл: выполнить строки с отступом для каждого элемента списка |
| `if условие:` + отступ | выполнить строки с отступом, только если условие верно |
| `name.startswith("UV_")` | верно, если строка `name` начинается с `UV_` |
| `name in [...]` | верно, если `name` есть в списке |
| `round(x)` | округлить число |
| `with open(путь, "a", encoding="utf-8") as f:` | открыть файл на дописывание (`"a"` — append) в кодировке UTF-8 (чтобы работала кириллица); после блока с отступом файл закроется сам |
| `os.environ["X"] = "1"` | задать переменную окружения `X` |
| `os.environ.pop("X")` | удалить переменную окружения `X` и вернуть её значение |

**Переменная окружения** — именованная настройка, которую видят все программы, запущенные из блокнота. Например, `HF_HOME` сообщает библиотекам Hugging Face, куда складывать скачанное.

## 5. Мини-справочник команд терминала

| Команда | Что делает |
|---|---|
| `set -e` | остановить скрипт на первой ошибке, чтобы не выполнять следующие команды впустую |
| `cd папка` | перейти в папку |
| `mkdir -p папка` | создать папку; `-p` — вместе с промежуточными, и без ошибки, если она уже есть |
| `rm -rf папка` | удалить папку целиком, **без корзины** |
| `ls -l папка` | показать содержимое; для ссылки — куда она ведёт |
| `ln -s куда имя` | создать ссылку `имя`, ведущую в папку `куда` (как ярлык в Windows) |
| `git clone адрес` | скачать репозиторий с GitHub; `-q` — без подробного вывода |
| `git checkout номер` | переключиться на конкретную версию (коммит) |
| `git log -1 --format='%h %cd'` | показать короткий номер и дату текущей версии |
| `source окружение/bin/activate` | «войти» в окружение: команды `python` и `uv pip` дальше работают в нём |
| `deactivate` | «выйти» из окружения |
| `команда1 \| команда2` | передать вывод первой команды на вход второй |
| `команда > файл` | записать вывод команды в файл (старое содержимое заменяется) |
| `grep -v -e A -e B` | пропустить только строки, в которых **нет** A и B |
| `grep -E "^(A\|B)=="` | оставить только строки, которые **начинаются** с `A==` или `B==` |
| `grep -o "шаблон"` | напечатать только совпавший кусок строки |
| `wc -l файл` | посчитать строки в файле |
| `\` в конце строки | команда продолжается на следующей строке |
| `python -c "код"` | выполнить код Python, записанный в кавычках |
| `python скрипт.py --опция` | запустить файл Python с опцией |

Команды `uv`:

| Команда | Что делает |
|---|---|
| `uv venv путь --python 3.11 --seed --clear` | создать окружение с Python 3.11. `--seed` кладёт туда базовые пакеты pip и setuptools, `--clear` заменяет старое окружение, если оно было |
| `uv pip install пакет` | поставить пакет в активное окружение |
| `uv pip install "пакет==1.2.3"` | поставить ровно эту версию |
| `uv pip install "пакет<81"` | поставить версию младше 81 |
| `uv pip install -r файл` | поставить всё из списка в файле |
| `uv pip freeze` | напечатать все пакеты окружения с точными версиями — так получается lock-файл |
| `uv pip check` | проверить, что версии пакетов совместимы между собой |

Кавычки вокруг `"пакет<81"` и `".[lm-eval]"` обязательны: без них терминал принял бы `<` и `[ ]` за свои спецсимволы.

## 6. Часть A по шагам

### Шаг 1. Подключаем Google Drive

```python
from google.colab import drive
drive.mount("/content/drive")
```

`drive.mount` подключает ваш Google Drive к машине Colab. После этого «Мой диск» виден как папка `/content/drive/MyDrive`, и Python может читать и писать туда файлы. В первый раз Colab попросит разрешение.

**Всё хорошо, если** напечаталось `Mounted at /content/drive` (или `Drive already mounted…`, если диск уже подключён).

### Шаг 2. Создаём папки проекта

```python
DRIVE = "/content/drive/MyDrive/unlearning_data"
FAST = "/content/fast"
os.makedirs(DRIVE + "/saves", exist_ok=True)
```

- `DRIVE` и `FAST` — две переменные с путями. Дальше пути собираются из них, например `DRIVE + "/saves"`.
- `os.makedirs` создаёт папку. `exist_ok=True` значит «если папка уже есть — ничего не делать»: ячейку можно запускать сколько угодно раз.
- На Drive создаются `saves` (сюда OpenUnlearning будет сохранять модели после «забывания») и `results_raw` (сюда пойдут журналы атак). На диске машины — `hf_home` (кэш Hugging Face) и `models` (модели, часть C).

### Шаг 3. Задаём переменные окружения

```python
os.environ["BIG"] = DRIVE
os.environ["HF_HOME"] = FAST + "/hf_home"
...
!echo $HF_HOME
```

- `BIG` — «большой диск» из плана. Команды плана вида `$BIG/saves` будут указывать на Drive.
- `HF_HOME` — папка, куда библиотеки Hugging Face складывают скачанное. Её нужно задать **до** первого импорта этих библиотек, поэтому шаг 3 идёт раньше шага 4.
- `MODELS` — папка для моделей (часть C).
- `TOKENIZERS_PARALLELISM=false` убирает лишние предупреждения токенизаторов. `PYTHONUNBUFFERED=1` заставляет программы сразу выводить текст, а не копить его, — так логи видны без задержки.
- `!echo $HF_HOME` печатает значение переменной и проверяет, что программы её видят.

**Всё хорошо, если** напечатались `/content/fast/hf_home` и `/content/fast/models`.

### Шаг 4. Подключаем токен Hugging Face

```python
os.environ["HF_TOKEN"] = userdata.get("HF_TOKEN")
print("Hugging Face:", whoami()["name"])
```

- Токен — это пароль к Hugging Face. Он хранится в секретах Colab (🔑 на левой панели) и **не пишется в коде**: иначе попал бы в GitHub.
- `userdata.get("HF_TOKEN")` достаёт секрет, а строка кладёт его в переменную окружения `HF_TOKEN`. Там его найдут все библиотеки и программы.
- `whoami()` спрашивает у Hugging Face, чей это токен. Так проверяется, что токен действует.

**Всё хорошо, если** напечаталось ваше имя на Hugging Face.

### Шаг 5. Смотрим GPU

`!nvidia-smi` печатает таблицу о видеокарте:

- название GPU (нужна L4, A100 или H100);
- объём памяти;
- версия драйвера;
- справа вверху — «CUDA Version», максимальная версия CUDA, которую поддерживает драйвер.

### Шаг 6. Записываем характеристики машины в журнал

```python
gpu = !nvidia-smi --query-gpu=name,memory.total,compute_cap,driver_version --format=csv,noheader
cuda = !nvidia-smi | grep -o "CUDA Version: [0-9.]*"
```

- Первая команда просит у `nvidia-smi` только нужные поля через запятую. Её вывод, например `NVIDIA L4, 23034 MiB, 8.9, 580.82.07`, попадает в список `gpu`, а `gpu[0]` — его первая строка.
- Вторая команда находит в таблице `nvidia-smi` кусок вида `CUDA Version: 12.8`.
- `psutil.virtual_memory().total` — объём оперативной памяти в байтах; деление на `1e9` (миллиард) даёт гигабайты. `shutil.disk_usage("/content").free` — свободное место на диске машины.
- `datetime.now(ZoneInfo("Europe/Moscow")).date()` — сегодняшняя дата по Москве. Часы Colab идут по UTC, и ночью без этого дата была бы вчерашней.
- f-строка собирает запись, а `with open(..., "a")` дописывает её в конец `journal.md` на Drive.

Если выполнить шаг ещё раз, запись добавится ещё раз. Лишнюю можно удалить, открыв `journal.md` на Drive.

## 7. Часть B по шагам

### Шаг 1. Старт сессии

Это шаги 1–4 части A в одной ячейке: подключить Drive, создать папки, задать переменные, взять токен. Добавлена одна папка — `envs` на Drive, для lock-файлов. Машина Colab каждый раз новая, поэтому эта ячейка — первая в каждом блокноте.

### Шаг 2. Ставим uv и убираем настройки Colab

```python
for name in list(os.environ):
    if name.startswith("UV_") or name in ["PYTHONPATH", "MPLBACKEND"]:
        print("Убираю", name, "=", os.environ.pop(name))
```

Colab настраивает всё под свой системный Python 3.13, и эти настройки ломают наши окружения. Цикл проходит по именам всех переменных окружения и удаляет три вида:

- `UV_…`. Из-за `UV_SYSTEM_PYTHON=true` программа `uv` ставила пакеты не в наше окружение, а в системный Python 3.13. Для него нет сборок torch 2.4.1, отсюда и была первая ошибка. `UV_CONSTRAINT` навязывала бы версии пакетов самого Colab.
- `PYTHONPATH` подмешивает модули Colab в любой запущенный Python, а наши окружения должны быть чистыми.
- `MPLBACKEND` велит matplotlib рисовать графики внутри блокнота. В окружении `atk` из-за неё падали vLLM и BERTScore — это была вторая ошибка.

`list(os.environ)` делает отдельный список имён, чтобы переменные можно было удалять прямо во время обхода. Строка `print` показывает, что удалено.

Потом `!pip install -q uv` ставит **uv** — быстрый установщик пакетов, который умеет создавать окружения со своим Python. В плане для этого была conda, но в Colab её нет.

### Шаг 3. Скачиваем OpenUnlearning

- `rm -rf /content/sandbox/open-unlearning` удаляет старую копию, чтобы шаг можно было повторять. Ссылка `saves` внутри копии удаляется как ссылка: файлы на Drive остаются.
- `git clone` скачивает репозиторий OpenUnlearning, а `git checkout 4ad738a…` переключает его на версию от 18 марта 2026 года. С этой версией сверен план. Новые изменения фреймворка не должны незаметно поменять числа в дипломе.
- `ln -s $BIG/saves saves` создаёт внутри OpenUnlearning ссылку `saves`, которая ведёт на Drive. Фреймворк думает, что пишет в свою папку `saves`, а файлы сразу оказываются на Drive и не пропадают вместе с машиной.

**Всё хорошо, если** напечаталось `4ad738a … Mar 18 … 2026` и `saves -> /content/drive/MyDrive/unlearning_data/saves`.

### Шаг 4. Окружение `unl`

- `uv venv /content/envs/unl --python 3.11 …` создаёт окружение с Python 3.11 (сам uv скачивает нужный Python). `source …/activate` входит в него.
- `uv pip install ".[lm-eval]"`: точка — «проект в текущей папке», то есть OpenUnlearning. Установщик читает его список зависимостей (`requirements.txt`: torch 2.4.1, transformers 4.51.3 и другие), а `[lm-eval]` добавляет дополнительную группу — библиотеку lm-eval для теста MMLU.
- `"setuptools<81"`: в новых версиях setuptools нет модуля `pkg_resources`, а без него не запускается TensorBoard 2.18 (просмотр кривых обучения в части D).

**Всё хорошо, если** в выводе есть `Using Python 3.11… environment at: /content/envs/unl` и нет слова `error`.

### Шаг 5. FlashAttention-2

FlashAttention — быстрая и экономная по памяти реализация «внимания» в трансформерах; её используют конфиги OpenUnlearning. Обычно её компилируют до часа, поэтому ставится готовый файл (wheel). Его имя расшифровывается так:

- `2.6.3` — версия;
- `cu123` — собран под CUDA 12;
- `torch2.4` — под torch 2.4;
- `cp311` — под Python 3.11;
- `linux_x86_64` — под Linux.

### Шаг 6. Логи оценки

`python setup_data.py --eval_logs` запускает скрипт OpenUnlearning. Он скачивает с Hugging Face результаты оценки готовых моделей. Метрика Forget Quality сравнивает вашу модель с эталонной, и готовые логи избавляют от её пересчёта. Файлы попадают в `saves/eval`, то есть через ссылку на Drive.

**Всё хорошо, если** в конце напечатаны папки вида `tofu_Llama-3.2-1B-Instruct_full`, `…_retain90` и другие.

### Шаг 7. Проверка `unl`

Код Python в кавычках импортирует главные библиотеки и печатает:

- `2.4.1+cu121` — версия torch (`+cu121` значит «собран под CUDA 12.1»);
- `12.1` — версия CUDA внутри torch;
- `True` — torch видит GPU;
- имя GPU;
- `4.51.3` и `2.6.3` — версии transformers и FlashAttention.

### Шаг 8. Lock-файл `unl`

`uv pip freeze` печатает все пакеты окружения с точными версиями. `grep -v` выбрасывает две строки — FlashAttention и сам OpenUnlearning, потому что они ставятся отдельно (шаги 3 и 5), а не из списка. `>` записывает остальное в `envs/requirements-unl.lock` на Drive. `wc -l` печатает число строк — около 115.

### Шаг 9. Окружение `atk`

Одна команда ставит всё сразу, чтобы uv подобрал версии, совместимые между собой. Что закреплено и почему:

- `vllm==0.19.1`. vLLM — «сервер» для быстрой генерации ответов: так атака разговаривает с моделями. 0.19.1 — последняя версия, собранная под CUDA 12. Более новые требуют CUDA 13, а Colab пока то включает, то откатывает CUDA 13.
- `transformers==5.5.3`, `tokenizers==0.22.2`, `huggingface-hub==1.10.2` — ровно те версии, с которыми разработчики тестировали vLLM 0.19.1.
- `setuptools<81` — как в тестах vLLM (про `pkg_resources` — в шаге 4).

### Шаги 10–11. Проверка `atk`

`%%writefile` записывает скрипт проверки в файл, шаг 11 его запускает. Скрипт проверяет три вещи:

1. PyTorch видит GPU, vLLM импортируется.
2. spaCy работает на GPU и находит в тестовом предложении имя (PERSON), город (GPE) и год (DATE).
3. BERTScore сравнивает два предложения и печатает число F1: чем оно больше, тем ближе смысл. При первом запуске скачивается модель roberta-large (около 1,4 ГБ).

Предупреждение `VisibleDeprecationWarning … toDlpack` безвредно: это пометка об устаревшей функции внутри библиотеки thinc, а не ошибка.

### Шаг 12. Lock-файл `atk`

### Шаг 13. Запись в журнал

`grep -E "^(torch|transformers|…)=="` находит в lock-файлах строки главных пакетов, а `", ".join(...)` склеивает их через запятую. Запись дописывается в `journal.md`: через месяц по ней видно, с какими версиями шли эксперименты.

### Шаг 14. Сборка из lock-файлов

Это проверка из блока 9 плана: окружения можно собрать заново и получить ровно то же самое. `uv pip install -r файл` ставит пакеты по списку из lock-файла. Для `unl` отдельно ставится FlashAttention — его в lock-файле нет.

Как проверить:

1. **Runtime → Disconnect and delete runtime** — получить чистую машину.
2. Выполнить шаги 1 и 2, затем шаг 14.
3. Выполнить проверки 7, 10 и 11.

## 8. Когда что-то пошло не так

**Как читать ошибку.** Ячейка печатает длинный текст (traceback), главное в нём — **последняя строка**: тип ошибки и сообщение. Строки выше показывают, в каком месте кода она случилась. Полезно прислать вывод целиком.

| Что видно | Причина | Что делать |
|---|---|---|
| `SecretNotFoundError: Secret HF_TOKEN does not exist` | в Colab нет секрета с именем ровно `HF_TOKEN` | добавить секрет (шаг 4 части A) и выполнить ячейку снова |
| `NotebookAccessError` | секрет есть, но этому блокноту не дан доступ | 🔑 Secrets → включить Notebook access |
| `Using Python 3.13… environment at: /usr` и ошибка про `cp313` | не выполнен шаг 2 части B, и uv ставит пакеты в системный Python | выполнить шаг 2, затем повторить упавший шаг |
| `ValueError: Key backend: 'module://matplotlib_inline…'` | не выполнен шаг 2 части B (осталась `MPLBACKEND`) | выполнить шаг 2, затем повторить упавший шаг |
| `CalledProcessError … returned non-zero exit status` | упала одна из команд в ячейке `%%bash` | смотреть строки **над** этой ошибкой: там настоящая причина |
| `No such file or directory` с путём `/envs/…` или `/saves` | не выполнен шаг 1: переменная `BIG` пустая | выполнить шаг 1, затем повторить |

Общее правило из плана: ничего не переустанавливать наугад. Прочитать последние строки вывода, найти причину, повторить шаг.

## 9. Когда пересобирать окружения

- **В каждой новой сессии**, где нужны `unl` или `atk`: шаги 1, 2 и 14 части B. Если нужен сам OpenUnlearning, то есть обучение и оценка, — ещё шаг 3.
- **Если в блокноте поменялись версии пакетов** (шаги 4, 5 или 9): выполнить шаги 1–13 заново. Lock-файлы перезапишутся, а в журнале появится новая запись о версиях. Так и должно быть: журнал показывает, когда менялось окружение.
- Командами `pip install -U` или `uv pip install -U` в рабочих окружениях ничего не обновляют: версии меняются только через блокнот, lock-файл и запись в журнале.
